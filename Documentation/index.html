MEM LLM Studio — Documentation

Welcome to the official user and developer manual for MEM LLM Studio. This turnkey platform enables autonomous local pre-training, fine-tuning, real-time telemetry monitoring, and interactive inference testing for Large Language Models directly on consumer NVIDIA GPUs and standard hardware.

1. Product Overview & Key Features

MEM LLM Studio solves the single biggest hurdle in local AI development: Out-Of-Memory (OOM) crashes. Traditional training scripts fail when GPU memory exceeds capacity. MEM utilizes an Autonomous Dynamic Lane Switching Engine that continuously monitors VRAM headroom and adjusts batch size, gradient accumulation, and context windows dynamically to ensure uninterrupted execution.

Key Feature Highlights:

  • Turnkey Zero-OOM Architecture: Dynamic lane promotion and demotion keeps VRAM safely bounded below hardware limits.
  • Pre-Configured Architecture Presets: Ready-to-train causal transformer models ranging from 50M, 75M, 130M, 250M, 400M, up to 540M parameters.
  • Streaming Dataset Integration: Direct streaming from Hugging Face datasets (FineWeb-Edu, SlimPajama, TinyStories) or custom local files (.txt, .jsonl, .csv) with zero multi-gigabyte disk pre-downloads.
  • Dual-Mode Visual Studio: Runs as a standalone Windows desktop app (via Chromium/Edge WebView) or accessible in any modern web browser.
  • Interactive Inference Playground: Test generated checkpoints instantly with real-time temperature, token limits, device selection, and copy-to-clipboard.
  • 1-Click Model Exporter: Export trained weights into industry-standard SafeTensors (.safetensors) and PyTorch (.bin) formats with HuggingFace config.json.

3. One-Click Installation

We provide an automated installation script that prepares the entire Python virtual environment and installs PyTorch with CUDA acceleration automatically.

Windows Automated Setup:

  1. Extract the purchased ZIP file to your preferred directory.
  2. Double-click install.bat.
  3. The script will automatically:
    • Verify Python 3.10+ is installed.
    • Create a clean virtual environment in mem_v3\.venv.
    • Detect your NVIDIA GPU and install PyTorch with CUDA 12.1.
    • Install required dependencies (safetensors, transformers, datasets, psutil, certifi).
  4. When installation completes, press any key to finish.
Linux / WSL Setup: If running on Ubuntu/Debian, simply run:
python3 -m venv mem_v3/.venv && source mem_v3/.venv/bin/activate && pip install -r mem_v3/requirements.txt

4. Launching the Studio

You can launch the Studio in two different ways:

  • Double-click start_studio.bat: Opens the application directly in a dedicated desktop window without browser URL bars.
  • Command Line: Run python MEM_Launcher.py and navigate your browser to http://127.0.0.1:8089.

5. Training LLMs (Step-by-Step Guide)

  1. Select Architecture: In the left configuration panel, choose your target parameter size (e.g. large_130m or ultra_500m).
  2. Select Dataset: Choose from curated high-quality datasets like HuggingFaceFW/fineweb-edu, DKYoon/SlimPajama-6B, or pick Custom to provide your own local text/JSONL file.
  3. Set Target Steps: Specify the number of steps (e.g. 10,000 to 100,000 steps).
  4. Select Initial Lane: Leave on Aggressive Throughput (default) — the autonomous governor will adjust if needed.
  5. Checkpoints: Keep Resume from Latest Checkpoint enabled to continue where you left off, or check Clean Start to archive old checkpoints and start fresh.
  6. Click Start Production Training.

6. Autonomous Zero-OOM Engine (How it Works)

MEM features an integrated AdaptiveLaneRunner governor. During execution:

  • Continuous VRAM Surveillance: Checks physical memory utilization every training window.
  • Dynamic Demotion: If allocated memory exceeds safe ceiling thresholds (e.g. >5.8 GB on 8 GB cards), the engine automatically downshifts to a safer lane with lower micro-batch size and higher gradient accumulation steps.
  • Dynamic Promotion: When throughput is stable and memory headroom is plentiful for 3 consecutive windows, the engine shifts up to maximize tokens/second.
  • WDDM Defragmentation: Proactively triggers cache purging to eliminate Windows driver allocation bloat.

7. Real-Time Telemetry & Analytics

The Studio features 7 live KPI cards updating every 1,000ms:

  • Global Step: Current progress and percentage bar.
  • Training Loss & Validation Loss: Real-time convergence metrics.
  • Throughput: Processed tokens per second (tok/s) and steps per second.
  • VRAM Allocation: Exact megabytes in use and hardware safety percentage.
  • Active Lane: Current operating mode badge and calculated ETA.
  • Lane Transitions: Number of autonomous lane switches performed.

8. Interactive Inference Playground

Verify your trained model's generation quality in real-time:

  • Custom Prompt: Enter any prompt or use quick presets (Story, AI Future, Physics).
  • Max Tokens Slider: Configure generation length from 10 up to 2,048 tokens.
  • Temperature Slider: Adjust sampling randomness from 0.05 (deterministic) to 2.0 (creative).
  • Inference Device: Choose Auto (safely uses CPU if training is running, or GPU if training is paused).
  • Copy to Clipboard: Copy generated output with one click.

9. Model Export & Packaging

Click Export Trained Checkpoint in the Studio to package your model for distribution. The exporter produces an exports/model_step_XXXX/ directory containing:

  • model.safetensors: High-speed zero-copy Safetensors weights.
  • pytorch_model.bin: Standard PyTorch state dictionary.
  • config.json: Complete architecture configuration (hidden size, layers, heads, vocab).
  • README.md: Example Python code to load the model in external applications.

10. REST API Reference

Integrate MEM LLM Studio into external dashboards, scripts, or client applications:

GET /api/state

Returns the complete live training telemetry, active step, loss history, and lane status.

GET /api/hardware

Returns GPU model name, total VRAM, allocated VRAM, CPU count, and free RAM.

POST /api/start

Starts a training job with JSON configuration:

{
  "model_preset": "large_130m",
  "dataset": "HuggingFaceFW/fineweb-edu",
  "steps": 25000,
  "start_lane": "aggressive_seq256_zero0_gacc4",
  "checkpoint_interval": 1000,
  "resume_latest": true
}
POST /api/inference

Runs model generation on the latest checkpoint:

{
  "prompt": "The future of autonomous computing",
  "temperature": 0.7,
  "max_tokens": 120,
  "device": "auto"
}
POST /api/export

Exports the latest checkpoint to SafeTensors and PyTorch format.

11. Troubleshooting & FAQ

Q: Port 8089 is already in use by another application.
A: MEM Studio automatically tries backup ports (8090, 8080, 8888) if 8089 is unavailable. The terminal prints the exact allocated URL.
Q: Windows socket error [WinError 10038] during streaming.
A: MEM Studio is equipped with native certifi certificate injection that prevents Windows socket handles from getting closed prematurely.
